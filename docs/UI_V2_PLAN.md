## 0. 集成策略（为什么这样做）

**目标**：能在真实（自动更新的）app 里日常测试新页面，又绝不因半成品页面把线上搞挂，
且避免「一条长命分支憋一大坨、最后一次性 merge 爆炸」。

**做法：功能开关（dark launch）+ 频繁小步合并到 master。**

- 新 UI 代码合进 master、随自动更新发给所有人，但**默认熄灭**，线上跑的仍是 legacy UI → 零风险。
- 开发者本机把开关打开，就是在真·安装版 app 里跑新 UI → 满足「真机测试」。
- 每做完一个页面就合一小块（藏在关着的开关后面）→ 无 merge 地狱。

**开关已落地**（commit `f879f21`，`cc_core.py`）：

- `CFG.UI_V2`（配置键）+ `DEFAULT_CONFIG[CFG.UI_V2] = False`（默认关）
- `UI_V2_ENV = "CC_UI_V2"`（环境变量名）
- `ui_v2_enabled(cfg)` 判定优先级：
  1. 环境变量 `CC_UI_V2` —— `1/true/yes/on` 强开，`0/false/no/off` 强关（一次运行有效，不写配置）
  2. 配置 `CFG.UI_V2` —— 内测者在设置里勾选（该 UI 层尚未接）
  3. 默认关 —— 线上用户无感

每个 v2 页面的接入形态：

```python
if ui_v2_enabled(self.cfg):
    return self._make_xxx_v2(...)     # 新 UI
return self._make_xxx_legacy(...)     # 老 UI，原样不动
```

开发者 dogfood：`$env:CC_UI_V2 = "1"; python translator.pyw`（或 `setx CC_UI_V2 1` 永久开）。

## 2. 关键洞察：先做地基，不是页面

POC 的科技感来自 PIL **烤**出来的「深蓝底 + 三色渐变（blue→violet→pink）+ 辉光 +（可选）
毛玻璃」PNG。真 app 复刻必须先有一个 **v2 皮肤层**，把这套背景烤成 `PhotoImage` 垫在控件后面。
**每个 v2 页面都依赖它。** 故 Phase 0 = 地基，是整条链的依赖起点，也是风险最高处。
地基跑通后，后续页面基本只是「换皮 + 挪组件」。

## 3. 依赖关系

```
Phase 0  v2 皮肤地基 (cc_ui_v2.py)
         ├ 调色板(navy + BRAND 三色渐变 + glass tint)
         ├ 背景烤制器(渐变 + 辉光 → PhotoImage, 随尺寸重烤/裁剪)
         ├ 圆角外壳集成(渐变填充 + 保留颜色键透明边)
         ├ 渐变文字 / 渐变胶囊按钮 / 状态点(避免豆腐块字形)
         └ 字体 + HiDPI 缩放
              │
   ┌──────────┼───────────┬───────────┬─────────┐
   ▼          ▼           ▼           ▼         ▼
[1]译文弹窗  [2]快速翻译  [3]历史    [4]设置   [5]关于
(+流式)      (小,复用)    (卡片流)    (最大)    (静态)
              │
        [6]诊断 / OCR (可选, 也可永远留 legacy)
```

除地基外，**页面之间无硬依赖**——每页独立 `if ui_v2_enabled(): _xxx_v2() else: _xxx_legacy()`，
故可一页一页合进 master、一页一页真机验证，永不大爆炸。

## 4. 开发顺序与理由

- **Phase 0 ｜地基**（`cc_ui_v2.py`，先不挂任何页面，离屏渲染 + 单测自验）
  先把最难的「圆角 + 渐变 + 辉光在真 tk 里」跑通，做成可单测的独立件。
- **Phase 1 ｜译文弹窗**（`_make_popup_v2`）——故意把最硬的放第一个。
  它①最常被看到②唯一有「流式实时增高」的极限性能场景。地基若扛不住流式重绘，第一天就暴露，
  而非投入五个页面后才发现。跑通它 = 地基被最狠用例验证过，后续静态窗口都更容易。
- **Phase 2 ｜快速翻译**——小而高频，复用 Phase 1 的渐变按钮 + 皮肤，快速拿成果。
- **Phase 3 ｜历史记录**——POC 已改卡片流，复用皮肤 + 列表滚动样式。
- **Phase 4 ｜设置**——最大、表单最多（下拉/开关/滚动条）。放后面，等 1–3 把
  「ttk 控件怎么坐在渐变上」的模式定下来再做，省返工。
- **Phase 5 ｜关于**——静态、简单，做成 showcase 收尾。
- **Phase 6 ｜诊断 / OCR**——可选，优先级最低，甚至永远留 legacy。托盘原生菜单放弃。

收尾：v2 默认开、稳定后，**一次性删除 legacy + 开关**。

## 5. 风险登记

| # | 风险 | 级别 | 缓解 |
|---|---|---|---|
| 1 | 流式增高每帧重烤渐变/毛玻璃 → 卡顿（弹窗约 20 次/秒长高） | 🔴 高 | 「一次烤到最大尺寸，之后只裁剪显示」；重烤节流；先出不透明 navy 渐变版，毛玻璃后续单独增强 |
| 2 | 毛玻璃(DWM acrylic) 与现有颜色键圆角透明冲突 | 🟠 中高 | 先不上 OS 毛玻璃；v1 用 PIL 假毛玻璃或纯不透明渐变；真毛玻璃单开 spike 验证 |
| 3 | ttk 表单控件坐在渐变上发虚/难看（主要影响设置页） | 🟠 中 | 渐变只用于头部/外框；正文区给一块实心内面板，ttk 控件坐实心底 |
| 4 | HiDPI / 多显示器：烤出的 PNG 要按窗口 DPI 缩放 | 🟠 中 | 按设备像素 + 实时字体度量烤图，DPI 变化时重烤 |
| 5 | 渐变上正文可读性 | 🟡 中低 | 正文一律放实心/近实心面板，渐变只做装饰件 |
| 6 | 过渡期同时维护 legacy + v2 两套，表面翻倍 | 🟡 中(流程) | legacy 全程不动、藏在关着的开关后；v2 默认开后一次性删除 |
| 7 | v2 是 GUI，测试难 | 🟡 中低 | 开关默认关 → 现有测试全走 legacy 不受影响；v2 加离屏 smoke 测试，用 env 门控 |

**风险总策略**：先出「不透明深蓝渐变 + 辉光」版本（毛玻璃与 OS acrylic 全部推迟），
**正文永远坐实心面板** → 绕开 1/2/3/5 里最尖锐的部分，先拿 80% 科技感，毛玻璃后续锦上添花。
