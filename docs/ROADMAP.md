# CC Translate — 迭代路线图（Roadmap）

本文件记录对 CC Translate 的迭代建议，来自一次整体代码走查与近期真实使用反馈。
按优先级分层，并标注当前状态。早期计划实施顺序：**1 → 3 → 2 → 5 → 6 → 4**，
新增方向见文末「下一阶段候选」，其余作为 backlog。

状态图例：⬜ 待办 · 🔄 进行中 · ✅ 已完成 · ⏸ 暂缓

---

## 🔴 高优先级（体验 / 正确性）

### 1. 保护用户剪贴板 ✅
- **问题**：双击 Ctrl+C 触发翻译时，用户选区会覆盖剪贴板原有内容，且从不还原，
  破坏用户正在进行的复制粘贴工作流（这类工具最常见的痛点）。
- **方案**：触发翻译前先保存当前剪贴板内容，读完选区后延迟把原内容还原回去。
- **风险**：低。仅在触发路径增加一次保存/还原。

### 3. 用户数据迁移到 %APPDATA% ✅
- **问题**：`config.json` / `history.json` / `perf.log` 都写在仓库目录（`APP_DIR`）。
  虽已被 gitignore，但会导致：只读安装失败、`git clean` 误删历史、多副本互相打架。
- **方案**：改用 `%APPDATA%\CC Translate\` 存放用户数据；首次启动时若旧位置存在数据则自动迁移。
- **附带收益**：为后续 macOS 移植（`~/Library/Application Support/`）铺路。
- **风险**：中。需保证向后兼容与一次性迁移。

### 2. 关键路径异常日志化 ✅
- **问题**：全文大量 `except Exception: pass` 静默吞掉异常，任何 bug 都无迹可寻，排查困难。
- **方案**：保留兜底不崩溃，但在关键路径（翻译调用、流式、剪贴板、配置读写、UI 构建）
  把异常写入 `perf.log`（复用已有 `log_perf`）。
- **风险**：低。只增加日志，不改变控制流。

---

## 🟡 中优先级（功能增强）

### 5. 历史详情富文本渲染 ✅
- **问题**：历史窗口的详情区是纯文本（`_rich=False`），与主弹窗的富文本体验不统一。
- **方案**：历史详情复用主弹窗的 markdown-lite 渲染，样式统一。
- **风险**：低。复用现成渲染器。

### 6. 代码块语法高亮（Pygments）✅
- **问题**：目前代码块只是等宽 + 灰底，没有按 token 上色。
- **方案**：为 ``` fenced 代码块接入 Pygments，按 token 类型着色，代码解释模式更像 VSCode。
  仅在定稿帧做，不进流式热路径，保证翻译速度不受影响。
- **风险**：中。新增可选依赖（缺失时优雅降级为纯等宽）。

### 4. 弹窗内一键换向 / 重译 ✅
- **问题**：译完想换翻译方向（如强制中→英）得进设置改，不顺手。
- **方案**：结果弹窗加一个小控件，一键切换方向并对当前选区重新翻译。
- **风险**：低。复用现有翻译管线。

## 🟢 Backlog（长期 / 架构，暂缓）

### 7. 代码 / 文本分类优化 ✅
- **已完成**：在模型调用前以纯本地、低成本的块级信号区分 text / mixed / code，
  覆盖 Python 结构、缩进与连续代码行，以及 JSON、YAML 和常见配置格式。
- **防误判**：普通表单、日期、路径和仅含少量括号或 `foo()` 的自然语言仍按文字处理；
  保留「作为文字翻译 / 作为代码解释」纠正入口，不增加分类用模型或网络请求。

### 8. 单文件拆分 ✅
- **已完成**：`translator.pyw`（曾达 7072 行 / 188 方法的 `TranslatorApp` god class）
  按功能拆入 11 个 mixin 模块，主文件回落到 **~1710 行**。纯机械搬迁，方法体零改动，
  对外行为零变化，286 个测试逐步保持全绿。
- **地基**：`cc_core.py`（GUI-free 叶子层——paths / logging / config keys /
  direction & prompt 常量 / themes & labels / 弹窗布局常量 / `StreamSession` /
  `fit_box_size` / `is_single_word` 等），translator.pyw `from cc_core import ...`
  全部 re-export，测试中的 `tr.<name>` 引用照常解析。
- **11 个 mixin**：`WarmMixin` / `UpdateMixin` / `TrayMixin` / `AboutMixin` /
  `QuickInputMixin` / `DiagnosticsMixin` / `HistoryMixin` / `SettingsMixin` /
  `OcrMixin` / `ResultActionsMixin` / `PopupMixin`。每个 mixin 只 import 叶子模块
  （cc_core / cc_warm / cc_ocr / cc_update / win32util / cc_rich / i18n），绝不
  import translator，避免 import 循环与「测试/生产双模块加载」陷阱。
- **注意**：mixin 拆分不降低运行期耦合（仍是单个实例、`self.` 调用不变）；对象级
  解耦是另一项高风险工作，本次不含。
- 遗留可选清理：`HistoryMixin` 仍用 lazy `import translator as _tr`（可后续改为
  cc_core 迁移 / wrapper）；config-IO 家族（CONFIG_PATH / load_config /
  _atomic_write_json / Config）仍留 translator，可按需单独迁入 cc_core。

### 9. 单元测试 ✅
- 纯函数（`classify_selection`、`code_ratio`、`iter_rich_segments`、`is_single_word`、
  `highlight_code`）最适合加单元测试，投入小、回归保护大。
- **已完成**：`tests/` 目录，37 个用例，覆盖分类/词典判定/markdown-lite 解析/
  流式安全/代码块高亮降级。用标准库 `unittest`，零新运行时依赖，对 app 功能无影响。
  跑法：`python -m unittest discover -s tests`（或 `pytest`）。

### 10. 打包分发 ⏸
- 用 PyInstaller 打成单个 `.exe`，普通用户双击即用，免装 Python 与依赖。

### 11. 自动检查 / 更新 ✅
- **需求**：本地程序能检查 GitHub 是否有新版本，有则更新并重启；支持夜间自动更新
  （设置里可开关）与手动更新。
- **方案**：app 本身是 `git clone` 部署，所以「更新 = `git pull --ff-only`」。
  - 检查：`git ls-remote origin master` 取远端 SHA 与本地 `HEAD` 比对（不落文件、不改本地）。
  - 更新：`git fetch` → `merge-base --is-ancestor` 确认可 fast-forward（本地分叉/领先则中止）
    → `git merge --ff-only`。
  - 安全护栏：更新后 `py_compile` + 跑单元测试，任一失败自动 `git reset --hard` 回滚并放弃重启。
  - 重启：启动一个分离的中转脚本（独立 `.ps1` 文件），轮询等当前进程退出（释放单例互斥锁）后再拉起新实例并在其秒退时重试，避免锁竞争；全过程写 `relaunch.log` 便于诊断。当前进程另有 `os._exit(0)` 兜底，确保非守护线程不会拖住旧进程、卡住重启。
    - ⚠️ 关键坑：中转脚本必须用 `CREATE_NO_WINDOW` **单独**创建，不能带 `DETACHED_PROCESS`。从无控制台的 `pythonw` 宿主派生时，`DETACHED_PROCESS`（无论是否与 `CREATE_NO_WINDOW` 叠加）会让无窗口的 PowerShell 助手根本不执行，导致重启静默失败；同时把子进程 stdio 重定向到 `DEVNULL`（`pythonw` 没有可继承的标准句柄）。
  - 无人值守安全：所有 git 调用禁用凭据弹窗（`GIT_TERMINAL_PROMPT=0`）+ 短超时，夜间检查不会卡住。
  - 优雅降级：非 git 部署 / git 缺失 / 网络失败均静默跳过，不影响正常使用。
- **配置**：`auto_update_enabled`（默认开，凌晨检查）、`auto_update_hour`（默认 3）。
- **入口**：设置「更新」区（版本号 + 夜间自动更新开关 + 检查更新按钮 + 发现新版本时才出现的「更新并重启」按钮）、托盘「检查更新」。手动「检查更新」只检查不改动，发现新版由用户点按钮决定；托盘「检查更新」会打开设置并触发同一处检查，两个入口收束到一处。夜间自动更新则在后台静默完成。
- **版本标识**：git 短 SHA + 提交日期（如 `9ef3615 · 2026-07-13`）。

## 🟠 下一阶段候选（基于近期真实使用反馈）

这些方向来自最近的真实安装 / 排障 / 日常使用反馈。与继续打磨纯视觉细节相比，
短期更有用户价值的是「可用性、可解释性、效率」。若只做 3 项，建议优先：
**12 → 13 → 14**。

### 12. 自诊断 / 健康检查 ✅
- **问题**：用户遇到“翻译不 work”时，很难分辨是未登录、执行策略、CLI
  不可用、自定义端点、网络失败、模型退役还是其它环境问题。
- **已完成**：托盘菜单已提供统一诊断页，可展示当前 Claude / OpenAI GPT Provider
  与模型、CLI 安装和认证状态、Claude / Codex 路由、脱敏后的关键环境变量与配置来源、
  自定义端点连通性、最近结果、本地词典状态及性能指标，并支持「重新检测」和
  「复制诊断信息」。
- **收益**：显著降低安装 / 排障成本，也方便远程支持。
- **风险**：中。要注意不泄漏 token，只显示必要状态。

### 13. 术语表 / 风格预设 ⬜
- **问题**：当前翻译虽可用，但缺少长期工作场景中的一致性控制（术语、语气、
  正式度）。
- **请求模型**：保持现有单次 LLM 请求，不增加术语识别或风格改写的第二次模型调用。
- **本地匹配**：
  - 调用模型前在本地扫描原文，只把本次实际出现的术语注入 prompt；没有命中时
    prompt 零增长。
  - 最长术语优先，避免短词抢占长短语；英文大小写匹配策略可配置，中文使用精确匹配。
  - 不直接替换原文，也不匹配代码块、URL 或文件路径，避免破坏输入及代码语义。
- **注入预算**：单次最多 10 条术语，总注入量约 500 字符；风格预设只追加一条
  短指令，超限时按最长术语优先后的稳定顺序截断。
- **缓存正确性**：缓存签名必须包含本次实际命中的术语及所选风格，避免不同术语 /
  风格上下文复用同一结果；无命中时不得因完整术语表变化而无效化无关缓存。
- **验证门槛**：实施前后使用固定样本做 A/B，对比结果一致性，并测量本地匹配 P95、
  模型首字耗时和完整完成耗时；三项均不能出现明显退化。
- **第一阶段范围**：
  - 术语支持「固定译法」和「不翻译」。
  - 风格提供「默认、简洁、正式邮件、技术文档」四种预设。
  - 暂不做云同步或复杂术语管理，先采用简单的本地配置与最小设置入口。
- **收益**：从「一次性翻译工具」升级为「可持续用于工作流」的工具。
- **风险**：中。重点防范误匹配、prompt 膨胀、缓存串用和模型耗时回退。

### 14. 结果后二次操作 🔄
- **问题**：用户看完结果后，常常还要再做一步（复制、改语气、继续追问、
  输出双语）。
- **已完成**：复制译文、复制双语、换目标语言重译，以及「更简洁 / 更正式 /
  提炼要点」操作均已进入结果弹窗。
- **仍待办**：解释术语 / 继续追问这段内容。
- **收益**：提高单次翻译后的转化效率，减少来回切换。
- **风险**：低到中。主要是按钮布局与上下文复用。

### 15a. 历史搜索 / 类型筛选与复用 ✅
- **已完成**：历史搜索、按模式筛选（译 / 词 / 码 / OCR）、一键重新翻译、
  复制结果和复制双语均已提供。
- **收益**：历史从「存档」变成「知识复用面板」。

### 15b. 历史收藏 / Pin ⬜
- **待办**：为常用历史记录增加收藏 / Pin，并补充持久化、排序和筛选状态。
- **风险**：中。需要避免与历史条数上限和自动清理规则冲突。

### 16. OCR 结果保格式 / 重选区域 ⬜
- **问题**：截图翻译的核心痛点不只是识别率，还包括换行、列表、代码块、表格等
  结构信息丢失；误框选时也缺少顺手修正。
- **方案**：
  - 尽量保留段落 / 列表 / 代码块结构
  - 对 OCR 结果做更好的行块合并
  - 允许截图后快速重选区域
- **收益**：显著提升截图翻译在文档、PPT、表格、代码截图场景下的可用性。
- **风险**：中到高。需要在不同来源的截图上做真实样本验证。

### 17. Provider / 后端解耦 🔄
- **问题**：当前真实环境里可能同时存在官方 Claude、Agent Maestro、
  自定义兼容端点等多种接法；一旦用户环境有代理 / 中转，行为和错误模式会显著
  变化。
- **已完成**：Claude CLI 与 OpenAI GPT（官方 Codex CLI）已有独立的请求、流式、
  预热、诊断和错误处理路径；Codex 原生配置可承接 ChatGPT 登录、API key 与兼容的
  自定义 provider，应用不复制凭据。
- **仍待办**：若未来直接接入更多非 CLI 后端，再收敛稳定的统一接口、能力声明和
  跨 Provider 错误分类；当前不为未落地后端预先扩张抽象。
- **收益**：降低环境耦合，便于诊断，也为未来扩展铺路。
- **风险**：高。偏架构演进，适合在功能稳定后集中推进。
